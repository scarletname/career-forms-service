# Сервис форм отклика

Менеджер сам собирает форму отклика на стажировку или мероприятие, публикует её по ссылке и смотрит ответы. Студент открывает ссылку и заполняет форму. Отдельно сервис показывает, **на каком вопросе студенты бросают форму**.

## Запуск

Нужен Node.js 20 или новее.

```bash
npm install
npm start
```

- Админка: http://localhost:3000/admin (без авторизации)
- Публичная форма: ссылка вида `http://localhost:3000/f/<код>`, её выдаёт админка после публикации

По умолчанию сервис слушает порт 3000. Другой порт задаётся переменной `PORT`:

```bash
PORT=8080 npm start              # macOS / Linux / Git Bash
$env:PORT=8080; npm start        # Windows PowerShell
set PORT=8080 && npm start       # Windows cmd
```

Если порт занят или `PORT` указан неверно, сервер завершается с понятным сообщением, без трассировки стека.

Данные лежат в `data/db.json`, файл создаётся при первом запуске. Чтобы хранить их в другом месте, задайте путь в `DATA_FILE`.

При первом запуске создаётся пример: опубликованная форма «Стажировка: Frontend-разработчик». Её можно сразу открыть, заполнить и посмотреть ответ в админке.

Тесты запускаются командой `npm test` (встроенный `node:test`, внешних зависимостей нет).

## Основной сценарий

1. **Менеджер собирает форму** в `/admin`: «+ Новая форма». Доступно 10 типов полей: короткий и длинный текст, email, телефон, ссылка, число, дата, один вариант, несколько вариантов, выпадающий список. У каждого поля есть вопрос, подсказка, пример ответа и признак «обязательное». Поля можно переставлять, дублировать и удалять. Изменения сохраняются автоматически, кнопки «Сохранить» нет.
2. **Публикация.** Кнопка «Опубликовать» проверяет форму: у каждого поля должен быть вопрос, у полей с выбором должны быть варианты ответа. Если всё в порядке, появляется ссылка с кнопкой «Копировать». Кнопка «Предпросмотр» показывает форму глазами студента, в том числе черновик.
3. **Студент заполняет форму.** Страница работает и с телефона. Ошибки показываются сразу, как только студент уходит с поля, а не только после нажатия «Отправить». Сверху есть индикатор прогресса. Ответы сохраняются в черновик браузера: если закрыть вкладку и вернуться, всё восстановится.
4. **Менеджер смотрит ответы** на вкладке «Ответы». Это таблица, по клику на строку ответ открывается целиком. Ответы можно выгрузить в CSV, который открывается в Excel без проблем с кириллицей.

Приём ответов можно закрыть: тогда студенты увидят «Приём откликов завершён». Форму можно скопировать для следующей стажировки.

## Почему студенты бросают форму

Это вторая проблема из задания, и для неё есть вкладка **«Аналитика»**:

- воронка: сколько студентов открыли форму, сколько начали заполнять, сколько отправили, конверсия и медианное время заполнения;
- по каждому вопросу: сколько студентов на него ответили и сколько ушли именно на нём;
- подсказка вида «Больше всего уходят на вопросе „…“» с советом, что с ним сделать.

Как это считается: браузер студента отправляет анонимные события «открыл форму», «начал заполнять», «корректно заполнил поле N». Идентификатор сессии хранится в localStorage и не сбрасывается после отправки, поэтому перезагрузка страницы или повторный заход не создают второго посетителя.

**Конверсия = посетители, отправившие форму / все посетители формы.** Она одинакова в списке форм и на вкладке «Аналитика». Если студент отправил форму дважды, в конверсии он учитывается один раз, а в таблице ответов два. Ответ, по которому до сервера не дошли события, всё равно учитывается как посещение, поэтому «отправили» никогда не превышает «открыли». Предпросмотр из админки в статистику не попадает, а вот открытие публичной ссылки самим менеджером попадает. Сессию без активности дольше 30 минут сервис считает брошенной. Студент «ушёл на вопросе», если последним заполнил вопрос перед ним. Пропущенные необязательные поля в середине формы на подсчёт не влияют.

## Технические решения

| Решение | Почему |
| --- | --- |
| Express и обычный JS без сборки | Единственная зависимость `express`. Минимум того, что может сломать `npm install` у проверяющего. |
| Хранение в JSON-файле, а не в SQLite | `better-sqlite3` собирается нативно и на чужой машине может не установиться, а `node:sqlite` нет в Node 20. Запись атомарная: сначала во временный файл, затем переименование. Частые сохранения объединяются в одну запись. |
| Одна схема валидации на сервере и в браузере ([shared/schema.js](shared/schema.js)) | Правила проверки описаны в одном месте. Браузер проверяет ради удобства, сервер — ради надёжности. |
| Мягкая проверка черновика, строгая — опубликованной формы | Менеджер может сохранить незаконченную форму. Опубликованную форму правка не сломает: сервер её не примет. |
| Устойчивые id полей | Ответы привязаны к id поля, а не к его порядку, поэтому перестановка полей ответы не ломает. |
| Защита в CSV | Значения, начинающиеся с `=`, `+`, `-` или `@`, экранируются, чтобы Excel не выполнил их как формулу. |
| Без `innerHTML` для пользовательских данных | Названия форм и ответы выводятся только как текст, поэтому XSS через форму невозможен. |

## Структура

```
shared/schema.js    типы полей и валидация (общие для сервера и браузера)
src/server.js       точка входа: PORT, путь к данным, пример формы
src/app.js          маршруты Express (админский и публичный API, страницы)
src/forms.js        логика форм: создание, публикация, ответы, события
src/analytics.js    расчёт воронки и мест, где студенты уходят
src/store.js        JSON-хранилище с атомарной записью
src/csv.js          выгрузка в CSV
public/admin.*      админка (одностраничное приложение на обычном JS)
public/form.*       страница формы для студента
test/               тесты API, валидации и аналитики
```

## API

Админка:

| Метод | Путь | Что делает |
| --- | --- | --- |
| GET | `/api/forms` | список форм со счётчиками |
| POST | `/api/forms` | создать черновик |
| GET / PUT / DELETE | `/api/forms/:id` | получить, сохранить или удалить форму |
| POST | `/api/forms/:id/publish`, `/close`, `/duplicate` | опубликовать, закрыть приём, скопировать |
| GET | `/api/forms/:id/responses` (`.csv`) | ответы (или выгрузка в CSV) |
| GET | `/api/forms/:id/stats` | воронка |

Для студента:

| Метод | Путь | Что делает |
| --- | --- | --- |
| GET | `/api/public/forms/:slug` | форма (404 для черновика, 410 для закрытой) |
| POST | `/api/public/forms/:slug/responses` | отправить ответы (422 с ошибками по полям) |
| POST | `/api/public/forms/:slug/events` | событие аналитики |

## Что не вошло и что я бы сделал дальше

- **Авторизация менеджеров и роли.** Сейчас админка открыта всем, как требует задание.
- **Версии формы.** При правке опубликованной формы старые ответы сохраняются, но ответ на удалённое поле пропадает из таблицы. Правильнее хранить снимок полей вместе с каждым ответом.
- **Защита от спама**: ограничение частоты запросов и капча на публичной форме.
- **Условная логика** («покажи вопрос, если выбран вариант X»), загрузка файлов (резюме), шаблоны форм.
- **Уведомления** менеджеру о новых откликах и письмо-подтверждение студенту.
- **SQLite или Postgres** вместо JSON-файла, когда понадобится масштаб и несколько процессов. Хранилище спрятано за `Store` и `forms.js`, поэтому замена затронет только эти два файла.
- **Аналитика**: источник перехода (utm-метки), разбивка по дням, время на каждом вопросе.
